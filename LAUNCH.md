## LinkedIn

> Ich habe in mein RAM-Werkzeug eine Funktion eingebaut, die nachweisbar nichts bringt — und sie im Programm auch genau so beschriftet.
>
> Real_RAM_cooler ist eine kleine Windows-Tray-App. Im Kern tut sie eine einzige nützliche Sache: Sie leert die Standby-Liste von Windows, über NtSetSystemInformation mit SystemMemoryListInformation und MemoryPurgeStandbyList — derselbe Mechanismus, den RAMMap -Et und ISLC benutzen. Der Anwendungsfall ist eng, und ich schreibe ihn genauso eng hin: Mikroruckler, wenn der Datei-Cache über Stunden aufgebläht ist. Keine FPS aus Luft, kein Ersatz für mehr RAM.
>
> Interessanter war für mich die zweite Hälfte. Was die Tuning-Branche als Hauptfunktion verkauft, ist EmptyWorkingSet über alle Prozesse: Working Sets werden getrimmt, die Zahlen im Task-Manager sehen aufgeräumt aus, Windows verschiebt den Inhalt in die Speicherkomprimierung und liest ihn beim nächsten Zugriff zurück. Ich habe sie eingebaut, weil man sie sehen können sollte. Ihr Ergebnistext lautet: „Gefühlt schneller: 100 %. Messbar schneller: 0 %.“
>
> Damit der Vergleich trägt, braucht es Messung statt Gefühl. Also ein Balken, der „verfügbar“ in drei Segmente auftrennt — in Benutzung, Standby, wirklich frei; der Standby-Anteil kommt aus drei PDH-Leistungsindikatoren. Dazu eine Prozessliste mit zwei Spalten, „Berührt“ (Working Set inklusive geteilter DLLs) und „Besitzt“ (privates Working Set, die Task-Manager-Zahl). Warum zwei Werkzeuge verschiedene Zahlen für denselben Prozess nennen, wird häufiger gefragt als beantwortet.
>
> Die Stelle, an der ich am längsten gesessen habe: Die App wendet den verspotteten Trick auf sich selbst an. Acht Sekunden nach dem Start und eine halbe Sekunde nach dem Minimieren ins Tray trimmt sie ihr eigenes Working Set. Das ist der einzige ehrliche Einsatzort dafür — ein Prozess, der im Leerlauf wartet, kann den Nachlade-Preis bezahlen, um dem Spiel nicht im Weg zu liegen. Diese Begründung steht als Kommentar im Code, damit die eigene Zahl im Task-Manager niemand als Werbeargument liest.
>
> Der Stand, ohne Politur: eine Quelldatei mit 1.167 Zeilen, zwei Fremdabhängigkeiten (pystray, pillow), sechs Windows-DLLs über ctypes. Kein Netzwerkaufruf — ein grep über den gesamten Quellcode nach urllib, requests, socket, http, Analytics und Telemetrie findet null Treffer. Kein Update-Check, kein Konto; geschrieben wird genau eine Datei, config.json mit acht technischen Werten.
>
> Die Kehrseite gehört dazu: Die App läuft mit Administratorrechten und aktiviert SeDebugPrivilege, kann also alle laufenden Prozesse einsehen. Der Gegenwert: jede dieser Zeilen liegt offen im Repository. Und der Installer ist nicht signiert — Windows zeigt „Unbekannter Herausgeber“, weil ein Code-Signing-Zertifikat mehrere hundert Euro im Jahr kostet.
>
> Windows 10/11 x64. Oberfläche, Doku und Installer sind ausschließlich deutsch, eine englische Fassung gibt es nicht. MIT-Lizenz.

**Text**

> Heads up before anything else: the interface, the readme and the installer are German only. There is no English build and I am not going to pretend otherwise. If that is a dealbreaker, RAMMap and ISLC do the same core job in English.
>
> The problem: after a few hours of uptime, games start micro-stuttering while Windows still reports plenty of memory as "available". A common cause is the standby list, the file cache that Windows holds rather than frees.
>
> The one intervention that actually helps is purging that list. This app does it through NtSetSystemInformation with SystemMemoryListInformation (0x50) and MemoryPurgeStandbyList (4), after enabling SeProfileSingleProcessPrivilege. Same call RAMMap -Et and ISLC make, so the same requirement applies: elevation on every launch. Without admin rights both action buttons are disabled and you get a read-only dashboard.
>
> Every purge prints a before/after line in plain text, and the memory bar splits Windows' "available" into three segments, in use / standby / actually free, with the standby figure read from three PDH counters. The process table shows working set including shared DLLs next to private working set, so it becomes obvious why two tools report different numbers for the same process.
>
> The part I built it for: a second button that calls EmptyWorkingSet on every process it can open. That is the trick most "RAM boosters" sell as their headline feature. Windows moves the trimmed pages into memory compression and faults them back in, so the button labels its own result "Gefuehlt schneller: 100 %. Messbar schneller: 0 %." — feels faster 100 %, measurably faster 0 %. Press it and watch Memory Compression grow in Task Manager. That is the whole reason it exists.
>
> Caveats, up front:
>
> * Windows 10/11 x64 only. Admin rights on every launch.
> * The installer is not code signed, so SmartScreen will warn about an unknown publisher. A certificate costs a few hundred euros a year and this is a hobby project. Click "Weitere Informationen", then "Trotzdem ausfuehren".
> * Purged cache has to be read back from disk. Hence the 120 second cooldown, and hence the automatic mode ships disabled. Aggressive thresholds cause more paging, not less stutter.
> * It does not create FPS and it does not replace more RAM.
> * No network calls at all: grep across the source for urllib, requests, socket, http, analytics and telemetry returns nothing. No update check, no accounts. One file gets written, config.json with eight keys.
> * It runs elevated and enables SeDebugPrivilege, so it can inspect every running process. In exchange the whole thing is 1,167 lines in a single readable file.
>
> Code: github.com/Dennismit2n/Real_RAM_cooler
> Download: github.com/Dennismit2n/Real_RAM_cooler/releases/latest
>
> MIT. Criticism of the approach is welcome, especially on the PDH counters and the Private Bytes fallback.

## Was ich bewusst nicht geschrieben habe

- **Kein „macht deinen PC schneller“, kein Wort über FPS.** Der echte Knopf behebt genau eine Sache: Stutter, der von einem vollgelaufenen Standby-Cache kommt. Er übertaktet nichts und ersetzt kein RAM-Upgrade. Das README sagt das selbst, und Werbung darf die eigene Dokumentation nicht überschreiben.
- **Die SmartScreen-Warnung steht in jedem Download-Aufruf, nicht in einer Fußnote.** Get-AuthenticodeSignature liefert für Setup und exe „NotSigned“, die Warnung kommt also garantiert. Wer sie verschweigt, lässt ein unsigniertes Systemwerkzeug mit Adminrechten genau im Moment der Installation wie Schadsoftware aussehen — das ist der teuerste Fehler, der hier möglich ist. Aus demselben Grund steht überall der Weg dabei: „Weitere Informationen“ → „Trotzdem ausführen“.
- **Kein „ein Klick, keine Hürden“.** Adminrechte sind bei jedem manuellen Start Pflicht, also jedes Mal ein UAC-Dialog; ohne Admin sind beide Aktionsknöpfe abgeschaltet und es bleibt der Anzeigemodus. Das ist keine Kleinigkeit, sondern der Preis dafür, dass der Eingriff echt ist — RAMMap und ISLC verlangen dasselbe.
- **Die Zahl „nur 10–15 MB Eigenverbrauch“ habe ich weggelassen**, obwohl sie im README steht. Sie ist nicht nachgemessen, sie ist die „Berührt“-Zahl, und sie entsteht teilweise dadurch, dass die App ihr eigenes Working Set trimmt — also durch genau den Trick, über den sie sich lustig macht. Im Code ist das ehrlich begründet; als nackte Werbezahl wäre es irreführend.
- **Kein „getestet“, „geprüft“ oder „stabil“.** Im Repo liegen keine automatisierten Tests. Belegbar ist stattdessen die Lesbarkeit: 1.167 Zeilen in einer Datei, zwei Abhängigkeiten — das darf man sagen, „getestet“ nicht.
- **Kein „besser als ISLC“ und kein Vergleich mit einer namentlich genannten Tuning-Suite.** Belegt ist nur, dass hier dieselbe API angesprochen wird wie von RAMMap -Et und ISLC. Was diese Programme im Übrigen können, habe ich nicht geprüft, also nenne ich meine eigenen Eigenschaften und lasse den Vergleich dem Leser. Beim Placebo-Knopf geht es entsprechend um einen Mechanismus — EmptyWorkingSet — und nicht um ein Fremdprodukt.
- **Kein „nichts bleibt zurück“, kein „portable“, kein „hält sich aktuell“.** Die Deinstallation räumt Autostart-Aufgabe und config.json weg, aber nur auf dem Installationsweg; eine blanke exe zum Mitnehmen gibt es nicht, die Release-Zip enthält Setup und README.txt; und es gibt keinen Update-Check, neue Versionen holt man selbst von der Releases-Seite. Drei kleine Versprechen, alle drei falsch.
